# 业务接口添加指南

本文档说明如何在这个项目中添加新的业务接口（非 CRUD 操作）。

## 核心原则

**Service 层直接使用 Repository，不通过 `dataProvider.custom`**

这样做的好处：
- ✅ `dataProvider` 保持简洁，只处理标准 CRUD
- ✅ 业务接口逻辑集中在 Service 层，职责清晰
- ✅ 不需要在 `dataProvider.custom` 中写大量 if-else
- ✅ 代码更易维护和扩展

---

## 完整步骤（推荐方式）

### 完整步骤

#### 1. 定义类型（`src/types/xxx.types.ts`）

```typescript
// src/types/report.types.ts
export interface UserReport {
  userId: string;
  username: string;
  totalOrders: number;
  // ... 其他字段
}

export interface UserReportService {
  getUserReport: (userId: string) => Promise<UserReport>;
  refreshUserReport: (userId: string) => Promise<void>;
  userReport: UserReport | null;
  loading: boolean;
}
```

#### 2. 在 Repository 接口中添加方法（`src/repository/data.repository.ts`）

```typescript
export interface DataRepository extends IPublicRepository {
  // 现有方法...
  getUserReport: (userId: string) => Promise<UserReport>;
}
```

#### 3. 在 Repository 实现中添加 HTTP 调用（`src/repository/data.repository.ts`）

```typescript
export const dataRepository: DataRepository = {
  // ... 其他方法
  
  getUserReport: async (userId: string): Promise<UserReport> => {
    const response = await httpClient.get(`/users/${userId}/report`);
    return response.data;
  },
};
```

#### 4. 在 Mock Repository 中添加 Mock 实现（`src/mock/data.mock.repository.ts`）

```typescript
export const dataMockRepository: DataRepository = {
  // ... 其他方法
  
  getUserReport: async (userId: string): Promise<UserReport> => {
    await delay(500);
    return {
      userId,
      username: `user_${userId}`,
      totalOrders: 100,
      // ... 其他 Mock 数据
    };
  },
};
```

#### 5. 在 DataProvider 中（可选，通常不需要）

**注意**：对于业务接口，我们**不推荐**在 `dataProvider.custom` 中处理。  
`dataProvider.custom` 现在只用于抛出清晰的错误提示，引导开发者使用 Repository。

```typescript
// src/providers/data.provider.ts
custom: async ({ url, method }) => {
  // 对于业务接口，建议在 Service 层直接使用 Repository
  // 而不是通过 dataProvider.custom 处理
  throw new Error(
    `Custom request is not supported. Please use Repository methods directly in Service layer for '${url}'.`
  );
},
```

#### 6. 创建 Service（`src/services/report.service.ts`）

**关键**：Service 层**直接调用 Repository**，不通过 `dataProvider.custom`。

```typescript
import { useCallback, useState, useEffect } from 'react';
import { realRepository } from '@/repository';
import { mockRepository } from '@/mock';
import type { UserReportService, UserReport } from '@/types/report.types';

// 根据环境变量选择 Repository
const USE_MOCK = import.meta.env.VITE_USE_MOCK === 'true';
const repository = USE_MOCK ? mockRepository : realRepository;

export const useUserReportService = (userId: string): UserReportService => {
  // 直接使用 Repository，不通过 dataProvider.custom
  const [userReport, setUserReport] = useState<UserReport | null>(null);
  const [loading, setLoading] = useState(false);

  // 获取用户报告
  const fetchUserReport = useCallback(async () => {
    if (!userId) return null;
    
    setLoading(true);
    try {
      const data = await repository.getUserReport(userId);
      setUserReport(data);
      return data;
    } catch (error) {
      console.error('Failed to fetch user report:', error);
      throw error;
    } finally {
      setLoading(false);
    }
  }, [userId]);

  // 初始化时获取数据
  useEffect(() => {
    if (userId) {
      fetchUserReport().catch(() => {
        // 错误已在 fetchUserReport 中处理
      });
    }
  }, [userId, fetchUserReport]);

  // 获取用户报告（异步方法）
  const getUserReport = useCallback(async (): Promise<UserReport> => {
    if (userReport) return userReport;
    try {
      const data = await fetchUserReport();
      return data || null;
    } catch (error) {
      throw error;
    }
  }, [userReport, fetchUserReport]);

  // 刷新用户报告
  const refreshUserReport = useCallback(async (): Promise<void> => {
    await fetchUserReport();
  }, [fetchUserReport]);

  return {
    userReport,
    loading,
    getUserReport,
    refreshUserReport,
  };
};
```

## 为什么不在 dataProvider.custom 中处理？

### ❌ 不推荐的方式（丑陋）

```typescript
// dataProvider.custom 中写大量 if-else
custom: async ({ url, method, payload }) => {
  if (url === '/dashboard/statistics' && method === 'get') {
    return { data: await repository.getStatistics() };
  }
  if (url === '/users/:id/report' && method === 'get') {
    return { data: await repository.getUserReport(payload.id) };
  }
  if (url === '/orders/export' && method === 'post') {
    return { data: await repository.exportOrders(payload) };
  }
  // ... 越来越多的 if-else，代码越来越丑陋
  throw new Error('Not supported');
},
```

**问题**：
- ❌ `dataProvider` 变得臃肿
- ❌ 业务逻辑分散在 Provider 层
- ❌ 难以维护和扩展
- ❌ 违反单一职责原则

### ✅ 推荐的方式（优雅）

```typescript
// dataProvider.custom 保持简洁
custom: async ({ url, method }) => {
  throw new Error(
    `Custom request is not supported. Please use Repository methods directly in Service layer.`
  );
},

// Service 层直接使用 Repository
export const useStatisticsService = () => {
  const [statistics, setStatistics] = useState(null);
  const [loading, setLoading] = useState(false);

  const fetchStatistics = useCallback(async () => {
    setLoading(true);
    try {
      const data = await repository.getStatistics(); // 直接调用
      setStatistics(data);
    } finally {
      setLoading(false);
    }
  }, []);

  useEffect(() => {
    fetchStatistics();
  }, [fetchStatistics]);

  return { statistics, loading, refreshStatistics: fetchStatistics };
};
```

**优势**：
- ✅ `dataProvider` 保持简洁，只处理标准 CRUD
- ✅ 业务逻辑集中在 Service 层
- ✅ 易于维护和扩展
- ✅ 职责清晰，符合架构设计

## 架构优势

通过这种方式，我们实现了：

1. **职责分离**
   - `dataProvider`：只处理标准 CRUD
   - `Repository`：封装 HTTP 调用
   - `Service`：处理业务逻辑和状态管理

2. **代码清晰**
   - 不需要在 `dataProvider.custom` 中写大量 if-else
   - 业务接口逻辑集中在 Service 层
   - 易于理解和维护

3. **易于扩展**
   - 添加新业务接口只需：定义类型 → 实现 Repository → 创建 Service
   - 不需要修改 `dataProvider`

4. **支持 Mock**
   - Repository 层自动根据环境变量选择真实或 Mock 实现
   - Service 层无需关心数据来源

## 常见问题

### Q: 如何添加 POST 请求的业务接口？

A: 在 Repository 中实现方法，然后在 dataProvider.custom 中处理：

```typescript
// Repository
exportUserData: async (userId: string, params: any): Promise<Blob> => {
  const response = await httpClient.post(`/users/${userId}/export`, params, {
    responseType: 'blob',
  });
  return response.data;
},

// DataProvider
custom: async ({ url, method, payload }) => {
  if (url === '/users/export' && method === 'post') {
    const blob = await repository.exportUserData(payload.userId, payload);
    return { data: blob as any };
  }
  // ...
},
```

### Q: 如何添加带参数的业务接口？

A: 在 Repository 方法中接收参数，在 Service 中通过 useCustom 的 payload 传递：

```typescript
// Repository
getUserReport: async (userId: string, dateRange?: { start: string; end: string }): Promise<UserReport> => {
  const params = dateRange ? { start: dateRange.start, end: dateRange.end } : {};
  const response = await httpClient.get(`/users/${userId}/report`, { params });
  return response.data;
},

// Service
const queryResult = useCustom<UserReport>({
  url: `/users/${userId}/report`,
  method: 'get',
  config: {
    params: dateRange, // 传递参数
  },
});
```
